# 任务调度系统问题修复 - 对齐文档

## 项目上下文
- **技术栈**: Python Flask + SQLAlchemy + Vue.js + Element Plus
- **架构模式**: 四层架构（数据层、服务层、应用层、表现层）
- **业务域**: 车辆调度任务管理系统

## 需求理解确认

### 问题1：标准容积与吨位对应关系
**当前状态**: 
- 标准容积字段为不可编辑状态
- 吨位选择后容积未自动更新
- 缺少标准吨位与容积的对应关系映射

**期望状态**:
- 建立标准吨位与容积的映射关系：
  - 5吨 ≥ 35m³
  - 8吨 ≥ 45m³  
  - 12吨 ≥ 55m³
  - 20吨 ≥ 100m³
  - 30吨 ≥ 130m³
  - 40吨A ≥ 150m³
  - 40吨B ≥ 180m³
- 选择吨位后自动计算并填充标准容积


### 问题2：实际容积填写时机
**当前状态**:
- 实际需求容积在派车时填写

**期望状态**:
- 实际容积由车间地调在发车环节确认时填写
- 派车时不应填写实际容积
- 实际容积字段在派车阶段应为隐藏状态

### 问题3：审核需求自动设置
**当前状态**:
- "是否需要审核"字段手动设置
- 缺少基于角色的自动逻辑

**期望状态**:
- 根据用户角色自动设置审核需求：
  - 区域调度员/超级管理员：自动设为"否"
  - 车间地调：自动设为"是"
  - 其他角色：隐藏此字段
- 审核需求字段应根据角色自动确定，无需手动设置

## 任务边界和验收标准

### 验收标准
1. ✅ 吨位选择后标准容积自动计算并填充
2. ✅ 标准容积字段保持不可编辑状态
3. ✅ 实际容积字段在派车阶段禁用/隐藏
4. ✅ 审核需求根据角色自动设置
5. ✅ 角色为"其他"时审核字段隐藏
6. ✅ 所有修改不影响现有功能

### 技术约束和依赖
- 前端：Vue 3 + Element Plus
- 后端：Flask + SQLAlchemy
- 数据库：现有字段结构保持不变
- 权限：基于现有角色系统实现

## 涉及的主要组件
- 前端：CreateTask.vue, TaskForm.vue
- 后端：dispatch_service.py, task.py模型
- 权限：permission.js store, 角色系统

## 风险评估
- 低风险：主要为前端逻辑调整，不影响核心业务
- 需要确保角色判断逻辑准确
- 需要测试吨位-容积映射的正确性
