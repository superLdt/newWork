# 车辆管理逻辑重构部署指南

## 概述

本次重构解决了车辆管理逻辑混乱的问题，将车辆管理分为两个清晰的概念：

1. **车辆日常管理** - 使用 `vehicle_capacity_reference` 表，管理车辆基础信息
2. **派车响应管理** - 使用 `vehicles` 表，管理任务相关的车辆信息

## 功能变更说明

### 前端变更

#### 车辆管理页面 (`/vehicle-management`)
- **变更前**: 对接 `/api/v1/vehicles` (vehicles表)
- **变更后**: 对接 `/api/v1/vehicle-capacity-reference` (vehicle_capacity_reference表)
- **功能调整**: 
  - 移除了派车任务相关字段（task_id、manifest_number等）
  - 移除了"更新容积"功能（这是派车任务相关功能）
  - 专注于车辆基础信息管理

#### 派车管理页面 (`/dispatch-tasks`)
- **保持不变**: 继续使用 `/api/v1/vehicles` (vehicles表)
- **约束加强**: 创建车辆时必须提供 task_id

### 后端变更

#### 新增API接口
- `GET /api/v1/vehicle-capacity-reference` - 获取车辆容积参考列表
- `POST /api/v1/vehicle-capacity-reference` - 创建车辆容积参考
- `PUT /api/v1/vehicle-capacity-reference/{id}` - 更新车辆容积参考
- `DELETE /api/v1/vehicle-capacity-reference/{id}` - 删除车辆容积参考
- `GET /api/v1/vehicle-capacity-reference/available` - 获取可用车辆
- `GET /api/v1/vehicle-capacity-reference/search` - 搜索车辆
- `GET /api/v1/vehicle-capacity-reference/vehicle-types` - 获取车辆类型选项

#### 数据模型变更

**VehicleCapacityReference 模型新增字段**:
- `carriage_number` - 车厢号
- `vehicle_category` - 车辆分类（单车/挂车）
- `frequent_companies` - 常用公司列表（JSON格式）
- `status` - 状态（active/inactive）
- `original_capacity` - 原始载重量

**Vehicle 模型约束变更**:
- `task_id` 字段设置为非空约束

## 性能影响

本次重构对性能的影响：

- **正面影响**: 数据分离后，查询更加精确，减少了不必要的数据加载
- **负面影响**: 增加了一个新表，但由于数据量分离，总体影响很小
- **建议**: 如果数据量很大，可以考虑为新表添加适当的索引
