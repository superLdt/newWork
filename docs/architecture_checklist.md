# 架构规则检查清单

## 后端四层架构检查清单

### 1. 表现层 (Presentation Layer) 检查项

- [ ] 路由文件位于正确的目录 (`backend/app/*/routes.py` 或 `backend/app/api/**`)
- [ ] 路由函数只处理HTTP请求和响应
- [ ] 路由函数不包含业务逻辑
- [ ] 路由函数正确调用服务层方法
- [ ] 参数验证在路由层完成
- [ ] 错误处理在路由层统一处理
- [ ] 路由函数返回统一格式的响应
- [ ] 不直接导入数据模型 (`models`)
- [ ] 只能导入服务层 (`services`)

### 2. 服务层 (Service Layer) 检查项

- [ ] 服务文件位于 `backend/app/services/` 目录
- [ ] 服务类封装业务逻辑
- [ ] 服务方法不处理HTTP请求/响应
- [ ] 服务方法可以调用数据模型
- [ ] 服务方法处理数据转换和验证
- [ ] 服务方法协调多个数据访问操作
- [ ] 服务方法实现事务管理
- [ ] 服务方法不应包含原始SQL查询

### 3. 数据访问层 (Data Access Layer) 检查项

- [ ] 模型文件位于 `backend/app/models/` 目录
- [ ] 模型类继承自 `db.Model`
- [ ] 模型类只负责数据定义和持久化
- [ ] 模型类不包含业务逻辑
- [ ] 模型类提供数据访问方法
- [ ] 模型类不处理HTTP请求
- [ ] 模型类只导入必要的扩展 (`extensions`)

### 4. 应用层 (Application Layer) 检查项

- [ ] 应用配置位于 `backend/app/config.py`
- [ ] 扩展初始化位于 `backend/app/extensions.py`
- [ ] 蓝图注册位于 `backend/app/__init__.py`
- [ ] 应用层不包含业务逻辑
- [ ] 应用层负责整合各层组件
- [ ] 应用层处理全局配置

## 依赖关系检查清单

### 允许的依赖关系

- [ ] 表现层 → 服务层 (允许)
- [ ] 服务层 → 数据层 (允许)
- [ ] 应用层 → 所有层 (允许)
- [ ] 数据层 → 扩展层 (允许)

### 禁止的依赖关系

- [ ] 表现层 → 数据层 (禁止)
- [ ] 服务层 → 表现层 (禁止)
- [ ] 数据层 → 服务层 (禁止)
- [ ] 数据层 → 表现层 (禁止)

## 文件组织检查清单

### 必需目录结构

- [ ] `backend/app/api/` 目录存在
- [ ] `backend/app/models/` 目录存在
- [ ] `backend/app/services/` 目录存在
- [ ] 各业务模块目录存在 (`auth`, `basic_data`, `dispatch` 等)

### 文件命名规范

- [ ] 路由文件命名为 `routes.py`
- [ ] 服务文件命名为 `*_service.py`
- [ ] 模型文件命名为 `*.py` (单数形式)
- [ ] API文件根据功能命名

- [ ] 组件保持单一职责
