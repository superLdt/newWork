# 任务执行计划与规范

## 任务执行流程

1. **需求确认**
   - 明确用户需求和期望结果
   - 确认技术约束和限制条件
   - 识别潜在风险和挑战

2. **任务细化**
   - 将复杂任务分解为具体子任务
   - 评估每个子任务的复杂度和依赖关系
   - 制定详细的执行步骤

3. **执行前检查**
   - 确认环境配置正确
   - 验证所需工具和依赖已安装
   - 备份重要文件（如需要）

4. **任务执行**
   - 按计划逐步执行子任务
   - 实时监控执行状态
   - 记录执行过程中的问题和解决方案

5. **验证与测试**
   - 验证任务执行结果是否符合预期
   - 进行必要的测试（单元测试、集成测试等）
   - 修复发现的问题

6. **文档更新**
   - 更新相关文档和注释
   - 记录变更内容和影响范围
   - 提供使用说明和注意事项

## 代码规范

### 后端代码分层架构规范

所有后端代码必须严格遵循四层架构：

1. **表现层 (Presentation Layer)**
   - 位置: `backend/app/api/` 和 `backend/app/*/routes.py`
   - 职责: 处理HTTP请求和响应，参数验证，调用服务层
   - 禁止: 包含业务逻辑，直接访问数据模型

2. **服务层 (Service Layer)**
   - 位置: `backend/app/services/`
   - 职责: 实现业务逻辑，处理数据转换和验证
   - 禁止: 处理HTTP请求/响应，直接处理原始SQL

3. **数据访问层 (Data Access Layer)**
   - 位置: `backend/app/models/`
   - 职责: 定义数据模型，实现数据持久化操作
   - 禁止: 包含业务逻辑，处理HTTP请求

4. **应用层 (Application Layer)**
   - 位置: `backend/app/`
   - 职责: 应用初始化和配置，模块注册和依赖管理
   - 禁止: 包含具体业务逻辑

### 前端代码规范

1. **组件化开发**
   - 使用Vue 3 Composition API
   - 组件应保持单一职责
   - 合理使用Props和Events进行组件通信

2. **状态管理**
   - 复杂状态使用Pinia管理
   - 遵循单向数据流原则
   - 状态变更应通过Actions进行

3. **路由管理**
   - 使用Vue Router进行路由管理
   - 路由配置应模块化组织
   - 实现路由守卫进行权限控制

## 命令行工具使用规范

### Windows环境注意事项

1. **命令分隔符**
   - 使用分号(`;`)而不是`&&`作为命令分隔符
   - 示例: `command1; command2` 而不是 `command1 && command2`

2. **路径分隔符**
   - 使用反斜杠(`\`)作为路径分隔符
   - 在脚本中使用`os.path.join()`处理路径

3. **批处理脚本**
   - 使用`.bat`文件处理复杂的Windows命令
   - 在脚本中正确处理错误和异常情况

### 开发环境启动

1. **使用Make命令**
   ```bash
   make dev
   ```

2. **手动启动**
   ```bash
   # 启动后端
   cd backend
   python run.py
   
   # 启动前端（新终端）
   cd frontend
   npm run dev
   ```

## 常见问题处理

1. **依赖安装问题**
   - 确保Python版本>=3.8
   - 确保Node.js版本>=16
   - 使用正确的包管理器(npm/pip)

2. **端口冲突**
   - 检查5000端口(后端)和3000端口(前端)是否被占用
   - 修改配置文件中的端口设置

3. **数据库问题**
   - 确保SQLite数据库文件有读写权限
   - 运行迁移脚本初始化数据库

4. **跨域问题**
   - 检查后端CORS配置
   - 确认前端API地址配置正确
